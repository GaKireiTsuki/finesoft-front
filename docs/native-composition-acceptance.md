后续精简与本轮独立对照见[框架进一步精简验收](framework-dedup-acceptance.md)。以下保留原生组合改造阶段的结果。

实施分支：`refactor/application-boundaries`。实现基于 `6f8d7c7`；性能与实现量对照独立检出的 `10fde72e70e8e932a2ae8c191828aea4c60e2632`，历史架构对照 `e22de64`。工作区保留了开始时未提交的方案修订，原文及补丁备份在 `reports/native-composition-implementation/`。

范围来自[修订后的方案](superpowers/specs/2026-09-16-native-composition-design.md)与[实施计划](superpowers/plans/2026-09-19-native-composition.md)。按用户要求，主体实现完成后才迁移并运行测试。所有结果均为本地代码及本地产物验证，未进行推送、发布或线上部署。

## 实现结果

- Core 直接执行归一化 handler；保留宿主覆盖、校验、策略、取消和生命周期。token/provider 取代字符串注册，类式控制器使用 `execute(input, context)`。
- 默认缓存键采用无歧义编码，不支持的数据明确失败；有界完成缓存与同 execution 的进行中查询复用保持独立。失效阻止旧结果回填并通知 Web 页面缓存。
- 页面定义拥有路由，共用路径编译与类型化目标。HTTP 支持参数路径、schema、方法分派及流资源释放。
- Web Runtime、导航事务与不可变展示快照形成唯一页面准备链。普通订阅者错误隔离，必需提交失败明确标记已提交。
- Browser 与 SSR 共享会话模型；水合使用 `{ tree, pages }`。原生根与组件生命周期归应用，Outlet 只订阅、渲染并确认实际提交版本。
- 六模板、原生 fixture、脚手架、公有入口、中英文文档同步迁移。旧 Framework、IntentDispatcher、多根 renderer/islands、URL-only session、旧生产启动与业务货架模型已删除。

## 验证与证据

2026-09-20 收尾：`vp check` 零警告、零错误；`vp test` 为 **104 个文件、772 项通过**；整仓 **17 项构建通过**。六模板生产浏览器、三套 minimal 独立挂载、六个工作区外的真实生成应用均通过。独立应用使用本地 tarball，分别运行 TypeScript 检查，Vue/Svelte 另跑原生组件检查，再构建客户端与 SSR。验证工具的 TypeScript 版本与仓库一致，未让自动 peer 安装升级为不兼容的 TypeScript 7。

原生 fixture 的 9 个 UI × 渲染模式组合、三框架初始 404/拒绝/重定向、Svelte tabs/split/嵌套 stack 均通过；其中同时检查 SSR 与浏览器上下文、上下文更新、实例/草稿保留、页面类型变化、真实链接与独立销毁。最后的独立复核发现并修复了忽略 AbortSignal 的旧请求阻塞新导航；修复后专项检查通过，没有剩余重要复核项。

## 接入成本与变更范围

独立数据接口需要 Operation、App、Runtime；公开 HTTP 时再声明 endpoint。普通 Web 页面需要页面声明（含路由）、原生视图表、原生 App/Outlet；浏览器与 SSR 使用同一个 App。组合导航只增加 tabs/stack/split 声明及相应业务控件，不修改原生绑定或增加另一套入口。

新增页面只改其业务加载、页面声明与视图表。类式 BaseController、module/implementation 分离、会话 provider 都是按实际业务选择的能力，不是最小页面的必填注册。

测试迁移删除了只验证已删除实现的套件；对应的用户行为迁入 Runtime/provider、统一 SSR、原生 fixture、history/commit 和 session 测试。没有在生产包中新增旧 API 兼容执行链。

## 可重复测量

生产测量脚本为 `scripts/measure-native-composition.mjs`；完整样本和构建标识写入 `reports/native-composition-implementation/measurements.json`。基线与当前使用相同 Node、依赖与生产模式，源码统计包含注释和空行，不把文件移动或格式压缩算作削减。

Node 为 `v24.21.0`，前后锁文件 SHA-256 相同。历史报告中的开发模式耗时不参与本轮生产对比。最终测量在功能验证结束后单独运行；SSR 与浏览器测量顺序执行，没有同时运行构建或其他验证。

### SSR、冷导入与内存

React minimal 生产模式，每轮预热 20 次、测量 100 次，三个前后交替轮次；每侧共 300 个 `Request → Response.text()` 样本。下表是本机确定性页面的框架成本，不含网络、TLS、代理或真实服务等待。

| 指标                        |     基线 |     最终 |
| --------------------------- | -------: | -------: |
| 完整响应中位数（ms）        | 0.139416 | 0.128708 |
| 完整响应 p95（ms）          | 0.287458 | 0.244250 |
| 序列化中位数（ms）          | 0.003625 | 0.003292 |
| 序列化载荷（字节）          |      873 |      791 |
| 完整 HTML（字节）           |     2451 |     2222 |
| 采样 heapUsed 中位数（MiB） |   13.115 |   13.192 |
| 采样 RSS 中位数（MiB）      |   74.906 |   71.203 |

完整响应三个轮次的中位数均较低；本次合并样本降低约 7.7%。序列化数值处于微秒级，不外推为用户感知收益。heapUsed 基本相当，RSS 的进程采样略低；没有做分配剖析，不能宣称已经证明每请求分配或峰值内存降低。资源正确性由作用域释放、缓存容量、离栈卸载和取消断言另外验证。

每个公开入口在 5 个新进程中测冷导入，中位数（ms）：

| 入口       |   基线 |   最终 |
| ---------- | -----: | -----: |
| 可移植根   |  1.374 |  1.727 |
| Browser    |  3.126 |  2.983 |
| 完整服务端 | 12.126 | 11.976 |

冷导入并未全部改善：可移植根入口增加约 0.35 ms，保留了严格缓存身份与路由等新增职责；Browser/服务端差异较小。这些数据不支持“所有启动路径更快”的结论。

### 浏览器生产流程

`measure-native-browser.mjs` 对三套 minimal 分别做三个交替轮次，每侧 15 个新浏览器上下文、150 次 tabs 导航。首次可操作指标为 navigationStart 到点击 Notes 得到可见页面，按帧重试，包含水合与该次切页；不是标准化 TTI。导航用页内 MutationObserver 测点击至可见 DOM 提交，不含 Playwright 轮询延迟，也不等同于绘制完成。

| 模板           | 首次可操作中位数（ms，前→后） | 导航中位数（ms，前→后） | 导航 p95（ms，前→后） |
| -------------- | ----------------------------: | ----------------------: | --------------------: |
| react-minimal  |                   49.2 → 49.6 |               1.0 → 1.0 |             1.1 → 1.2 |
| vue-minimal    |                   48.4 → 49.3 |               0.9 → 0.9 |             1.1 → 1.1 |
| svelte-minimal |                   49.1 → 49.2 |               0.9 → 0.9 |             1.0 → 1.1 |

浏览器耗时差异与帧、计时精度及本机波动相当，**未测得稳定改善**。本轮确定收益是职责/实现量减少、查询与保存工作次数减少、原生组合正确性以及局部 SSR/包体改善；未把所有性能目标标为改善。

### 验证边界

Node 和真实本地 Worker 已执行 Request/Response、执行隔离及资源生命周期验证；部署适配器验证为本地生成产物与依赖边界。没有向 Vercel、Netlify、Cloudflare 或生产服务器发布，也没有将本地结果表述为线上验收。

若业务 handler 忽略取消信号，后续导航仍可提交；旧结果不能覆盖当前页面。旧 handler 的资源保留至它实际结束，销毁会等待它，框架不会假装已经终止任意业务 Promise。
