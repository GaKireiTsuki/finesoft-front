# 框架代码精简实测（2026-09-20）

本轮保留现有能力，合并了已确认等价的重复实现。源码从 **13,870 行降至 13,765 行，减少 105 行（0.76%）**，没有达到减少一半以上的目标。

基线是本地 `64e6be3`：包含此前 11 项误移除回归的修复。测量时主工作区的源码与该检查点一致，修改在 `refactor/reduce-runtime` 隔离工作区完成。代码行数不包含测试、文档、声明产物和构建输出，也没有通过删除注释、压缩排版、转移文件或新增依赖来计算降幅。

## 实际修改

| 范围            | 合并的重复实现                               | 源码净减少 |
| --------------- | -------------------------------------------- | ---------: |
| Web navigation  | 激活路径遍历、栈目标解析及更新               |      73 行 |
| Core runtime    | 操作完成事件、成功/失败后的 Promise 记账清理 |      10 行 |
| Browser history | 四种 history 写入路径                        |       7 行 |
| 部署适配器      | 临时入口构建与清理、预渲染文件输出           |      15 行 |

导航保留了两种不同的查找语义：显式目标找最近的栈，默认目标找激活路径上最深的栈；查找首个匹配容器时仍提前结束。历史记录仍区分缓存页面状态和仅写 URL，并保留滚动恢复与导航序号处理。

独立复核发现，Netlify 原有 FIFO 缓存与共享 LRU 的淘汰顺序不同，不能视为等价重复，已撤回该项改动。Provider 构造、导航结果装配的辅助层试验增加了代码，也已撤回。注入的控制器、页面操作边界、预取身份、运行时与请求资源生命周期继续保留。Action/modal、非结构化 URL 导航、markPublic/public projection、请求隔离和三种原生渲染器没有删减。

## 体积与性能

基线与修改后使用相同依赖锁文件和 Node v24.21.0。SSR 使用生产模式，3 轮交替独立进程，每侧 300 次采样；浏览器使用 Chrome 153，每种渲染器每侧 15 个新上下文、150 次切换。

| 本地指标              |      修改前 |      修改后 |
| --------------------- | ----------: | ----------: |
| SSR 中位耗时          |    0.1346ms |    0.1331ms |
| SSR P95               |    0.3242ms |    0.2700ms |
| React 导航中位 / P95  | 1.0 / 1.2ms | 1.0 / 1.2ms |
| Vue 导航中位 / P95    | 0.9 / 1.1ms | 1.0 / 1.1ms |
| Svelte 导航中位 / P95 | 0.9 / 1.1ms | 0.9 / 1.1ms |

首个可交互页面中位耗时：React 48.9→49.3ms，Vue 49.2→49.2ms，Svelte 48.7→49.1ms。入口冷导入中位耗时分别为 portable 1.81→1.86ms、browser 3.21→3.20ms、完整 server 12.35→12.89ms。SSR 堆内存采样中位约 14.43→14.42MB、RSS 约 74.51→74.56MB。这些样本没有显示明显性能退化，也不足以宣称普遍加速或证明没有内存泄漏。

六套模板的客户端 JS 原始字节均减少约 1.65KB，逐文件 gzip 总量减少 162–195 字节（0.19%–0.43%）。体积与源代码统计分别报告。

以上是本地确定性模板和进程测量，不覆盖生产网络、真实设备和长时间负载。浏览器导航测量到 DOM 提交，首交互测量有动画帧分辨率。原始数据、脚本和日志在 `reports/runtime-reduction/`；`measurements.json` 记录测量时源码哈希、提交、差异与产物哈希。回放基线应使用 `64e6be3` 的独立检出，而非已应用修改后的主工作区。
