## Fixes, refinements and remaining limits

- Root/subentry isolation, strict declaration consumers and exact publish restoration are implemented. Node production entry no longer re-exports the development server/Vite path. Optional UI peers are physically absent in unselected consumers; graph inspection alone is not the proof.
- `definePage` is a thin typed reference, not a new executor or view DSL. Handler/factory parameter and literal result typing is tested; widened BasePage, arbitrary codec-to-handler equivalence and native component prop validation are not promised.
- M1 strict serialization now remembers marked/unmarked materialization. Already-aborted supplied execution now receives cancellation before admission rejection; original signal, scope and owner are retained. RED coverage output is preserved as task7-coverage-red.log.
- Static adapter now uses built routes/shared SSR assembly and awaited cleanup, fails discovery/rendering errors, supports explicit dynamic/routesExport inputs, and rejects non200/redirect/runtime-only headers including Set-Cookie. Its generated HTML was hydrated in Chrome.
- Scaffolder output now has standalone tsconfig and selected Hono peer; create-app and runtime build configs use actual Vite+ pack configuration. Svelte templates have explicit config. AGENTS generated-marker damage was repaired; existing CI policy was documented without workflow edits.
- Current EN/ZH guides, templates and live demos use final imports and APIs. Ch02 handles asynchronous Router.resolve; both language route/guard demos were exercised. Historical plans/review are clearly marked historical, not rewritten as current instructions.
- Generated-install logs contain peer-range warnings with the intentionally pinned Vite alias (`@voidzero-dev/vite-plus-core@0.2.8`; public vite peer>=5). The installed tooling consumer has strict declarations and actual import/build passes. This metadata warning remains visible; no dependency upgrades were introduced.
- Adversarial fixture builds deliberately warn when Node-only test controllers are imported into their browser diagnostic graph. Ordinary public portable/browser graphs are separately verified clean. Local workerd does not validate Cloudflare deployment, and Chrome-only native evidence does not claim Firefox/WebKit conformance.
