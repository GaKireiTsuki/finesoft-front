# Action 与职责收敛

用户要求 Action 同时负责普通 URL 与结构化导航，并消除同职责的薄转发层。本次在已有导航生命周期、历史和服务解析修复上继续实施。

实施状态：已完成，验证结果与测量限制见[实施报告](../../unified-actions-report.md)。

## 统一入口与所有者

- `Action` 统一包含 Flow、栈、Tab、Split、实例复用、刷新、整树恢复、ExternalUrl 和 Compound。结构化动作直接带类型化参数，不再另设 `NavigationOperation`、`NavigationCommands`、`apply` 或便捷导航方法。
- WebSession 直接成为 ActionDispatcher 的执行实例，持有唯一快照、事务队列和条目缓存；`perform`、自定义处理器注册及组合执行均属于该对象。Browser 不再另外构造分发器或暴露 `actionDispatcher`。
- 导航树纯函数继续负责不可变树变换，Action 处理器直接调用它们进入原有守卫、加载、提交和原生确认流程。
- History 桥只负责历史记录、滚动恢复与清理，移除重复的导航句柄。原生链接也进入同一个 Action 执行器。
- SessionStore 直接向页面提供持久化和作用域能力；浏览器会话桥只负责恢复门控、定时保存和生命周期绑定。浏览器直接扩展原 Store 对象，DOM 恢复通过其 getter 读取最新作用域，消除逐方法代理。

## 保留语义

普通 URL 导航只挂载当前页面；显式结构化导航保留树中条目。同址 URL 刷新原实例，显式 push 仍创建新实例。模态使用独立页面会话，组合动作按顺序执行，自定义处理器仍可显式替换。拒绝、重定向、取消、缓存失效、SSR 请求隔离、持久化恢复和原生提交确认继续沿用已有事务实现。

数据 Operation 的 query/command、Runtime 和执行作用域具有独立语义与资源寿命，保留其真实职责；公开打包入口及原生 UI 绑定也继续维持依赖边界。

## 实施与验收

1. 合并 Action 类型及执行对象，删除导航命令与桥接转发，迁移所有消费者。
2. 收拢会话持久化和 DOM 状态访问，更新公开文档和架构说明。
3. 实施后验证混合动作、全部导航形态、模态、自定义扩展、拒绝和取消；运行完整测试、检查、构建及真实原生浏览器/六模板验证。
4. 对比本次开始前的工作区代码量，单独报告运行时代码变化，不将此前修复、文档或测试删除混算为收益。
