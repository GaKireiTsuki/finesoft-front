# WebSession 状态收敛实施

依据主工作区 `docs/superpowers/specs/2026-09-20-model-consolidation-design.md` 的 WebSession 方向，基线为已验证的 `4b3fa62`。继续保留全部能力；允许同步调整 API、包内归属与消费者。按用户要求先完成实现，再测试。

## 实施任务

1. 将导航事务实现收敛为 `createWebSession`。同一所有者维护树、按 EntryId 索引的页面记录、稳定挂载顺序、失效信息和 revision；成功提交只生成并通知一份 AppSnapshot。删除独立 `createAppView` 状态及其订阅。必需提交步骤接收前后快照，仍在原生通知前运行；错误聚合和原生确认顺序不变。
2. WebSession 直接实现持久化导航端口，删除 navigation adapter 转发对象。序列化、作用域身份、异步存储、provider、版本和深链恢复门控保持独立。Browser、SSR 和 modal 直接消费会话；首次失败用显式 start 边界呈现安全错误，不提交拒绝候选或泄露其页面数据。
3. 同步迁移公开导出、类型、仓库消费者、文档和测试。旧控制器/视图的测试迁移到真实会话接口，不删去原有行为断言；增加单次快照/通知、前后状态一致性和持久化直连验证。
4. 实施后运行相关测试、vp check、完整测试、全部构建、原生浏览器和六模板独立应用验证。比较基线和新实现的页面加载次数、通知次数、耗时与源码/产物；经过独立安全差异审查后，将通过验证的增量同步回主工作区，保留原有改动，不推送。

## 验收边界

- push/pop/tabs/split、同页双实例、隐藏草稿、modal 隔离、取消及迟到结果、history/scroll、重载恢复、拒绝/重定向、页面类型变化继续可用。
- EntryId、ResourceKey、revision、导航取消代次保持不同含义。组件内部状态仍由原生 UI 持有；markPublic 出站投影不与本地 session 数据混用。
- 唯一状态所有者是真实替换旧对象；不保留并行旧实现或添加只转发的 WebSession 外壳。原型若存在缺陷，继续修正；不能将未知收益当成已获得的删码。
