# 独立 Controller 的路由类型自动维护

用户目标：保持独立 class 与独立路由注册；参数类型只在路由声明。用户已明确选择「框架自动生成并维护源码中的类型引用」。

## 已验证的边界

- 标准 TypeScript 不为独立类的方法、覆写箭头属性或合并接口自动补齐方法参数；实测均得到 TS7006。
- 语言服务插件不能替代命令行检查；Vite+ 使用 TypeScript Go / tsgolint。
- 通过页面引用反向关联 BaseController 泛型会出现类型循环；生成的输入声明需要独立于控制器返回类型。

## 方案

1. 工具仅在开发/构建配置运行，读取 TypeScript 程序，按 definePage 的 create 返回类定位控制器；不执行业务模块或构造函数。
2. 复用 RouteInputFor 推导路由输入，生成项目内的 .finesoft/controller-types.d.ts。类文件只补入框架管理的类型引用；参数形状仍由路由唯一决定。
3. 保留 class、execute/fallback、实例成员、既有返回页面泛型和执行链。手写类型不被静默覆盖；模板的迁移按用户授权显式处理。
4. 接入 Vite 配置与源码监听，并验证 vp check 实际配置加载行为。为非 Vite 调用暴露同一生成函数；避免维护多套类型生成逻辑。
5. 仅在内容改变时写文件；生成前检查源文件未被并发修改。生成器及 TypeScript 编译依赖隔离在工具入口。

## 验收

- 分文件的类接收到数字/可选/查询参数；重命名字段与改变 codec 自动更新类型引用指向的声明。
- 编辑器语言服务提供成员补全；错误调用与旧字段由原生 vp check 检出，不能用 any 或过滤诊断代替。
- 多别名与共享控制器合并输入，保留现有严格工厂兼容检查。
- 重跑生成无无意义修改，不覆盖手写业务实现；代码生成不进入浏览器和服务运行产物。
- 恢复 ProductDetailController 与集中路由注册，迁移共享模板；完成类型、运行、打包和浏览器验证。
