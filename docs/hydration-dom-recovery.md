# SSR DOM 变化的通用恢复

2026-09-21。SSR DOM 恢复实现及发布前验证记录；准确版本与发布状态以 Git 标签和 npm 为准。

## 行为

SSR 组装阶段为数据脚本所属容器生成 DOM 校验值。浏览器消费 SSR 数据后，在返回原生挂载句柄前比较当前 DOM。比较属性、文本、注释和结构，不维护浏览器插件名单，不猜测修改来源。

检测到变化且不存在受保护的浏览器状态时，现有 `shouldHydrate` 返回 false，React、Vue、Svelte 模板直接使用各自原生 mount 路径。页面数据沿用已有 SSR 缓存，控制器不重复执行。正常页面继续水合，后续 SPA 导航不运行这项检查。

焦点、选区、已改表单、滚动、可编辑内容、活动媒体、自定义元素、嵌套应用和不透明浏览器上下文会阻止额外重建，继续原生水合并保留诊断。自定义元素宿主及内部内容不参与校验，避免把组件升级与声明式 Shadow DOM 的解析当作外部变化。

日志字段为 `source: hydration`、`code: dom-changed`，`recovery` 为 `native-mount` 或 `deferred`。不清洗 DOM，不修改原生水合错误处理，不过滤全局控制台，不循环重建。

## 验证

- `vp check --fix`：格式、lint、类型检查通过。
- `vp run --filter '@finesoft/front...' build`：通过，HTML 解析依赖随服务端实现打包。
- `vp test`：116 个测试文件、990 项通过。前一次并行全量运行有一项既有文件监听测试超时；单文件复测及最后完整复测均通过。
- `vp exec node scripts/verify-external-hydration.mjs`：Chrome 中 React、Vue、Svelte 共 25 个场景通过。覆盖正常 SSR、未知属性、内联样式、文本替换、节点插入/删除、根外修改、预先输入的文字，以及 React 自身的水合属性不一致。
- 三种原生 UI 均验证了重建后的输入响应；有输入时保留原节点和原值。应用自身的 React 水合不一致仍报告错误，未知属性但已输入的保留路径也保留原生警告。
- 额外验证 HTML 实体、SVG 命名空间、表格补全、模板、注释、nonce、自定义元素和声明式 Shadow DOM 的服务端/浏览器校验一致。
- 读取正在运行的组件文档首页及 Quick start 的实际 SSR HTML，再在隔离浏览器中比较 DOM 校验值。此项为真实输出的校验及耗时测量，没有替换文档项目当前安装的框架版本，也不是新版框架下完整文档交互验收。

实际文档采样每项运行 7 次，以下为本机中位数，不代表所有设备：

| 页面        | 校验样本大小 | DOM 元素数 | 服务端生成 | 浏览器校验 |
| ----------- | -----------: | ---------: | ---------: | ---------: |
| 首页        |    约 358 KB |        222 |   10.24 ms |    1.20 ms |
| Quick start |    约 640 KB |        677 |   18.31 ms |    2.60 ms |

采样保留 SSR 内容，阻止原应用启动并去掉外部资源引用；自定义元素内部不参与校验。验证脚本可额外接收保存的 HTML 文件路径来重做采样。

## 边界与接入状态

这不是安全校验，也不是扩展隔离。页面外部样式、组件自己管理的内部状态、检查之后的 DOM 改动、扩展独立执行环境中的通信错误均不由此修复。保留原生水合也不能保证原生渲染器自身出错时不丢状态。

标准模板和 `injectSSRContent` 自动接入；手工 HTML 未带校验值或数据脚本不直接位于 target 内时保持原有行为。上述文档采样基于 `@finesoft/front@0.5.2` 的原始输出；发布后接入新版的结果由组件仓库 `docs/docs-finesoft-front-migration.md` 记录。

文档整站 locale 应声明在 `defineWebApp.configuration.locale` 中，由 SSR 在 `<html>` 输出 `lang`、`dir`。应用容器继续保留自己的 locale 属性和 `data-fs-app`，以维持嵌入应用及事件委派的边界。
