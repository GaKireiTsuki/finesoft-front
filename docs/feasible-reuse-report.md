# 可行复用改进实施报告

依据高层重构方案和共用声明原型验证报告，本批已实施模板中立源码物化、守卫循环共用和 Web 非阻塞观察者共用。未采用已有净增代码及声明快照回归的页面执行原型；WebSession 已在后续批次完成实施及验证，见 [WebSession 实施报告](web-session-report.md)。

实施基线为 `c7b9f7b226e1d9ac40135f1b93aa5e04e85ef9d4`，代码提交终点为 `6121a37721e48881d07fe500f5eb3c210be0895c`。相对基线的固定补丁在 `reports/feasible-reuse/final-implementation.patch`，SHA-256 为 `b04dd9596f9b1cefdd185f96668cf0297103c9011d806f7a071af2c499169d08`。

## 实际改进

- full/minimal 中立源码分别以 `templates/react/src`、`templates/react-minimal/src` 为唯一维护源。50 个 Vue/Svelte 重复文件由安装、开发启动、构建及脚手架发布准备生成；保留各自原生组件、入口与 appId。生成器记录文件所有权，拒绝覆盖修改过的副本，只删除自己生成且未修改的旧文件。`templates/README.md` 说明维护与 watch 流程。
- beforeLoad/afterLoad 使用同一泛型循环，保留两种输入类型、前后取消检查和首个非 next 短路。Web 的两个观察者通知入口共用一个私有函数；不改变提交步骤、原生确认、日志错误和资源释放的语义。
- 浏览器验证发现基线已有的恢复问题：单叶初始未知地址根返回首页时，原实现只向错误栈压入页面。现在通过已有初始导航解析入口恢复声明结构；正常导航仍保留原分支和页面身份。
- 三套最小模板删除错误页的多余链接处理，统一由现有 Browser 宿主处理普通链接。实测 Svelte 的一次点击原先提交两次、产生两个首页；修复后仅保留正确导航。browser/memory 模式、应用作用域及原生修饰键行为继续由宿主维护。

## 验证结果

先实施，再运行验证：

- `vp check`：格式、lint、类型检查通过。
- `vp test`：109 个文件、855 项测试通过。新增生成器所有权/清理、守卫取消/异常、观察者异常隔离及初始未知地址恢复断言。
- `vp run -r build`：17 个构建及 4 个模板同步前置任务通过。
- 从冻结提交归档创建无生成副本的新目录，`vp install` 自动生成全部 50 个文件，逐字节匹配各自唯一源。
- 六套脚手架产物在仓库外安装本地 front tarball，TypeScript 和 Vue/Svelte 原生类型检查、client/SSR 构建通过；产物不含仓库内部同步钩子。tarball SHA-256：`e823e6d5e170327a216eda8ecc21b9cf8af8a1d80a408869cc75ec48d1596f15`。
- 浏览器 9 组验证通过：六套生产预览及三套开发模式独立挂载。覆盖 SSR/CSR、导航、草稿与重载恢复、history、locale、错误页返回和 memory 挂载，未记录控制台或 hydration 错误。额外断言错误页返回不出现重复首页造成的 Back 按钮。
- Codex Security `assess-patch-risk` 对固定差异独立检查，未发现可操作缺陷；审查属于风险建议，不代表线上验收。

本地构建入口性能比较：7 轮交替执行，每轮每场景预热 300 次、采样 3,000 次；两侧严格核对守卫、处理器及两类通知次数。

| 场景                             | 基线中位数 | 本批中位数 |
| -------------------------------- | ---------: | ---------: |
| 带前后守卫的 URL 页面加载        |  12.156 μs |  11.597 μs |
| 带前后守卫、导航及视图通知的导航 |  19.908 μs |  19.733 μs |

未观察到性能退化；这是本地微基准，存在 JIT/调度噪声，不证明线上延迟或内存泄漏情况。数据和复现脚本在 `reports/feasible-reuse/performance.json`、`measure-runtime.mjs`。验证日志、浏览器结果和独立消费者结果集中在同一目录。
